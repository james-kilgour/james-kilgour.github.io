Working in the R/tidyverse space for a while now has been very rewarding: I’ve always had a tech slant to my hobbies and interests but my technical proficiency has really deepened over the last twelve months. One project I’m particularly proud of was a prototype R Shiny dashboard centered on the idea of “streaks” that I finished before summer. It was a completely new way of looking at the data in our programme; shifting away from the monthly reporting of performance data and more towards a focus on long-term - much more difficult to sustain - trends. I ended up re-writing everything in SQL to take advantage of the newly available database access my team had secured and save on local processing at the same time.

Calculating performance streaks in SQL

The “streaks” calculation has a few parts. It starts by simply setting up the first of four CTEs in SQL, meta_data, a table of reference values for each performance indicator.

#| eval: false
WITH meta_data AS (
    SELECT DISTINCT
        measure_id,
        CAST(reference_point AS DECIMAL) AS ref_point
    FROM eic.eic_all_data
    WHERE reference_point IS NOT NULL
)

From here, we query the actual data itself and perform some low-level formatting tweaks to help with reporting later on, creating calculated_data.

#| eval: false
calculated_data AS (
    SELECT
        hb_name,
        TRUNC(measure_date_my, 'MM') AS measure_date_my,
        sub_location_code,
        measure_id,
        CAST(calc_rate AS DECIMAL) AS calc_rate,
        high_rate_is_better_flag
    FROM eic.eic_overview
    WHERE hb_name = '", board,"'
)

Then those two tables get joined (in joined_data no less, points for unorinality?), so we know what certain teams achieved in a given month, how that compared to the national reference value, and a flag variable to help with the counting later on.

#| eval: false
joined_data AS (
    SELECT
        c.*,
        m.ref_point,
        CASE
            WHEN calc_rate >= ref_point AND high_rate_is_better_flag = 1 THEN 1
            WHEN calc_rate <= ref_point AND high_rate_is_better_flag = 0 THEN 1
            ELSE 0
        END AS success_flag
    FROM calculated_data c
    LEFT JOIN meta_data m
        ON c.measure_id = m.measure_id
)

Turning joined_data into groups, I then go over each team for each health board, and create a new group each time a data point lapses and a streak breaks while keeping the monthly ordering stable so we can accurately identify consistent patterns. It’s a little funny to read, but essentially what this code does is say “starting from 0, count how many zeros are in this team’s whole run”.

#| eval: false
groups AS (
    SELECT
        *,
        SUM(CASE WHEN success_flag = 0 THEN 1 ELSE 0 END)
            OVER (
                PARTITION BY hb_name, measure_id, sub_location_code
                ORDER BY measure_date_my
            ) AS grp
    FROM joined_data
)

Finally, we get the last table output which tallies sequential successes in each group and helps us identify the maximum streak value.

SELECT
    *,
    CASE
    WHEN success_flag = 1 THEN
        SUM(success_flag) OVER (
            PARTITION BY hb_name,
                         measure_id,
                         sub_location_code,
                         grp
            ORDER BY measure_date_my
            ROWS UNBOUNDED PRECEDING
        )
    ELSE 0
END AS success_streak
FROM groups
ORDER BY
    hb_name,
    measure_id,
    sub_location_code,
    measure_date_my
